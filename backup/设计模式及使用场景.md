设计模式（Design Patterns）是软件工程中对常见问题的可复用解决方案。GoF（Gang of Four）经典模式分为 **创建型**、**结构型**、**行为型** 三大类。以下精选 15 个最常用模式，按类别列出核心场景与语言无关的伪代码，便于快速理解与落地。

---
## 🟦 一、创建型模式（Creational）
关注对象的创建过程，将对象的实例化与使用解耦。

### 1. 单例模式 `Singleton`
- **场景**：全局唯一实例，如配置中心、连接池、日志器、硬件驱动管理。
- **伪代码**：
```pseudocode
class Singleton {
    private static instance = null
    private constructor() { /* 初始化资源 */ }
    
    static getInstance() {
        if instance == null:
            instance = new Singleton()
        return instance
    }
}
// 使用：logger = Singleton.getInstance()
```
> ⚠️ 实际需考虑线程安全（如双重检查锁、静态内部类、枚举单例等）。

### 2. 工厂方法 `Factory Method`
- **场景**：同一产品族，具体类型由子类/配置决定。如不同数据库驱动、支付渠道、消息序列化器。
- **伪代码**：
```pseudocode
interface Product { process() }
class ProductA implements Product { process() { print("A") } }
class ProductB implements Product { process() { print("B") } }

abstract class Creator {
    abstract createProduct(): Product
    doSomething() {
        p = createProduct()
        p.process()
    }
}
class CreatorA extends Creator { createProduct() { return new ProductA() } }
```

### 3. 抽象工厂 `Abstract Factory`
- **场景**：创建**一系列相关/依赖**的对象，客户端不关心具体实现。如跨平台 UI 控件族（Win/Mac）、主题皮肤、数据库驱动族。
- **伪代码**：
```pseudocode
interface Button { render() }
interface Checkbox { render() }

interface UIFactory {
    createButton(): Button
    createCheckbox(): Checkbox
}

class WinFactory implements UIFactory {
    createButton() { return new WinButton() }
    createCheckbox() { return new WinCheckbox() }
}
// MacFactory 同理
```

### 4. 建造者 `Builder`
- **场景**：构造复杂对象，步骤多、参数爆炸，或需要不同配置组合。如 SQL 构建器、HTTP Request、文档/报表生成。
- **伪代码**：
```pseudocode
class House { foundation, walls, roof, interior }

interface Builder {
    buildFoundation()
    buildWalls()
    buildRoof()
    getHouse(): House
}

class Director {
    constructor(builder: Builder)
    construct() {
        builder.buildFoundation()
        builder.buildWalls()
        builder.buildRoof()
    }
}
```

### 5. 原型模式 `Prototype`
- **场景**：对象创建成本高，或需要基于现有对象快速克隆（如游戏角色复制、配置快照、深拷贝缓存）。
- **伪代码**：
```pseudocode
interface Prototype { clone(): Prototype }

class Monster implements Prototype {
    hp, attack, skills
    clone() {
        return new Monster(this.hp, this.attack, deepCopy(this.skills))
    }
}

// 使用
original = new Monster(100, 10, [fireball])
clone = original.clone()  // 独立副本
```

## 🟨 二、结构型模式（Structural）
关注类与对象的组合方式，形成更大的结构。

### 6. 适配器 `Adapter`
- **场景**：接口不兼容的类需协同工作。如旧系统 API 对接新框架、第三方 SDK 包装、数据格式转换。
- **伪代码**：
```pseudocode
interface Target { request() }
class Adaptee { specificRequest() { print("legacy") } }

class Adapter implements Target {
    private adaptee: Adaptee
    constructor(adaptee) { this.adaptee = adaptee }
    request() { adaptee.specificRequest() }
}
```

### 7. 装饰器 `Decorator`
- **场景**：动态为对象添加职责，替代继承爆炸。如 I/O 流包装、HTTP 中间件、缓存/日志/鉴权包装器。
- **伪代码**：
```pseudocode
interface Component { operation() }
class ConcreteComponent implements Component { operation() { print("base") } }

class Decorator implements Component {
    protected component: Component
    constructor(c) { this.component = c }
    operation() { component.operation() }
}

class LoggingDecorator extends Decorator {
    operation() {
        log("before")
        super.operation()
        log("after")
    }
}
```

### 8. 代理 `Proxy`
- **场景**：控制对对象的访问。如懒加载（虚拟代理）、权限校验（保护代理）、远程调用（远程代理）、结果缓存。
- **伪代码**：
```pseudocode
interface Subject { request() }
class RealSubject implements Subject { request() { print("real work") } }

class Proxy implements Subject {
    private real: RealSubject
    request() {
        if real == null: real = new RealSubject()  // 延迟初始化
        checkPermission()
        real.request()
    }
}
```

### 9. 外观 `Facade`
- **场景**：为复杂子系统提供统一简单接口。如电商下单流程封装、编译器前端、硬件抽象层。
- **伪代码**：
```pseudocode
class SubsystemA { opA() }
class SubsystemB { opB() }
class SubsystemC { opC() }

class Facade {
    private a = new SubsystemA()
    private b = new SubsystemB()
    private c = new SubsystemC()
    
    simpleWorkflow() {
        a.opA()
        b.opB()
        c.opC()
    }
}
```

### 10. 组合 `Composite`
- **场景**：树形结构，统一处理叶子与容器。如文件系统、UI 组件树、菜单/部门组织架构。
- **伪代码**：
```pseudocode
interface Component {
    operation()
    add(Component)
    remove(Component)
}

class Leaf implements Component {
    operation() { print("leaf") }
    add() { throw Error }
    remove() { throw Error }
}

class Composite implements Component {
    private children = []
    operation() { for c in children: c.operation() }
    add(c) { children.push(c) }
    remove(c) { children.remove(c) }
}
```

## 🟩 三、行为型模式（Behavioral）
关注对象间的职责分配与通信机制。

### 11. 观察者 `Observer`
- **场景**：一对多依赖，状态变化自动通知。如事件总线、消息订阅、MVC 模型驱动视图、实时数据推送。
- **伪代码**：
```pseudocode
interface Observer { update(data) }

class Subject {
    private observers = []
    attach(o) { observers.push(o) }
    detach(o) { observers.remove(o) }
    notify() {
        for o in observers: o.update(this.state)
    }
}
```

### 12. 策略 `Strategy`
- **场景**：算法可互换，运行时动态切换。如排序/压缩算法、支付方式、折扣计算、路由策略。
- **伪代码**：
```pseudocode
interface Strategy { execute(data) }

class StrategyA implements Strategy { execute(d) { print("algo A") } }
class StrategyB implements Strategy { execute(d) { print("algo B") } }

class Context {
    private strategy: Strategy
    constructor(s) { this.strategy = s }
    setStrategy(s) { this.strategy = s }
    run(data) { this.strategy.execute(data) }
}
```

### 13. 命令 `Command`
- **场景**：请求封装为对象，支持撤销/重做/队列/日志。如 GUI 按钮操作、事务系统、宏录制、任务调度。
- **伪代码**：
```pseudocode
interface Command {
    execute()
    undo()
}

class LightOnCommand implements Command {
    private receiver: Light
    constructor(r) { this.receiver = r }
    execute() { receiver.turnOn() }
    undo() { receiver.turnOff() }
}

class Invoker {
    private history = []
    setCommand(c) { this.history.push(c) }
    run() { this.history.last().execute() }
    rollback() { this.history.pop().undo() }
}
```

### 14. 模板方法 `Template Method`
- **场景**：定义算法骨架，子类重写可变步骤。如框架生命周期、报表生成流程、爬虫解析管线。
- **伪代码**：
```pseudocode
abstract class DataProcessor {
    pipeline() {
        loadData()
        transform()      // 子类实现
        saveData()
        cleanUp()        // 可选钩子
    }
    loadData() { print("default load") }
    abstract transform()
    saveData() { print("default save") }
    hook cleanUp() { }   // 空实现供重写
}
```

### 15. 状态 `State`
- **场景**：对象行为随内部状态改变，消除大量 `if/switch`。如订单状态机、游戏角色状态、工作流引擎。
- **伪代码**：
```pseudocode
interface State { handle(context) }

class PaidState implements State { handle(ctx) { print("deliver goods") } }
class ShippedState implements State { handle(ctx) { print("confirm receipt") } }

class OrderContext {
    private state: State
    constructor(s) { this.state = s }
    setState(s) { this.state = s }
    next() { this.state.handle(this) }
}
```

## 📌 使用建议与避坑指南
| 原则 | 说明 |
|------|------|
| **按需引入** | 不要为了“用模式”而用。先写简单代码，重构时再提取模式。 |
| **语言特性优先** | 现代语言已内置部分模式能力（如 Python/JS 用函数+闭包替代策略，Go 用接口组合替代继承结构）。 |
| **组合优于继承** | 装饰器、策略、代理等模式本质是通过组合实现动态扩展，避免类爆炸。 |
| **模式可混合** | 实际项目常组合使用，如 `工厂 + 策略`、`观察者 + 命令`、`外观 + 适配器`。 |
| **警惕过度设计** | 简单 CRUD 或一次性脚本不需要模式；高内聚低耦合才是核心目标。 |

> 💡 提示：伪代码为概念示意，实际实现需结合语言特性（如泛型、并发控制、依赖注入容器等）。建议配合 UML 类图与开源项目源码（如 JDK、Spring、React、Laravel）对照学习。
