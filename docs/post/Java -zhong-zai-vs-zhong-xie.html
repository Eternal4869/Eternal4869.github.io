Java 重载vs重写

在Java中，重载（Overload） 和重写（Override） 是两个极易混淆但又至关重要的概念。它们都与“方法”有关，但发生的场景、遵循的规则以及底层原理截然不同。

一句话概括核心区别：

  • 重载发生在同一个类中，是方法名相同，参数列表不同（编译时多态）。
  • 重写发生在父子类之间，是方法名和参数列表完全相同，子类覆盖父类的实现（运行时多态）。

一、 核心区别对比表

对比维度 重载 (Overload) 重写 (Override)
发生位置 同一个类中 父子类之间（或接口与实现类之间）
方法名 必须相同 必须相同
参数列表 必须不同（个数、类型、顺序至少一个不同） 必须完全相同
返回值类型 可以不同（但不能仅靠返回值不同来重载） 可以不同（但必须是协变返回：子类返回值类型 $\le$ 父类）
访问修饰符 可以不同 子类不能比父类更严格（如父类protected，子类不能是private）
异常抛出 可以不同 子类不能抛出比父类更宽泛的受检异常
多态类型 编译时多态（静态绑定/早期绑定） 运行时多态（动态绑定/晚期绑定）

二、 重载 (Overload) 详解

1. 什么是重载？

在同一个类中，允许存在一个以上的同名方法，只要它们的参数个数、参数类型或参数顺序不同即可。
通俗理解：就像“打印”这个动作，你可以打印一张纸，也可以打印一本书，虽然都叫“打印”，但处理的对象（参数）不同。

2. 代码示例

public class Calculator {
    
    // 方法1：两个整数相加
    public int add(int a, int b) {
        return a + b;
    }

    // 方法2：重载方法1（参数个数不同）
    public int add(int a, int b, int c) {
        return a + b + c;
    }

    // 方法3：重载方法1（参数类型不同）
    public double add(double a, double b) {
        return a + b;
    }

    // 方法4：重载方法1（参数顺序不同，虽然不推荐这么写，但语法上合法）
    public String add(String a, int b) {
        return a + b;
    }
    public String add(int b, String a) {
        return a + b;
    }

    // ❌ 错误示范：仅返回值不同，不能构成重载！
    // public double add(int a, int b) { return a + b; } 
    // 编译器无法仅通过返回值类型来决定调用哪个方法。
}

3. 重载的绑定机制

重载是在编译阶段就决定了调用哪个方法的。编译器会根据你传入的参数类型和个数，在编译时确定唯一的方法签名。因此，重载被称为编译时多态或静态绑定。

三、 重写 (Override) 详解

1. 什么是重写？

子类重新定义父类中已有的方法。当子类对象调用该方法时，会执行子类重写后的逻辑，而不是父类的逻辑。
通俗理解：父亲教了儿子“如何做饭”，但儿子觉得父亲的做法不好吃，自己发明了新做法。别人让儿子做饭时，儿子用的是自己的新做法。

2. 核心规则（经典口诀：“两同、两小、一大”）

要成功重写父类方法，必须严格遵守以下规则：

  • 两同（必须相同）：
    1. 方法名相同。
    2. 参数列表相同。
  • 两小（子类 $\le$ 父类）：
    1. 返回值类型小（或相同）：如果父类返回 Object，子类可以返回 String（协变返回）；如果父类返回基本类型 int，子类必须也是 int。
    2. 抛出的异常小（或相同）：子类不能抛出比父类更宽泛的受检异常（Checked Exception）。
  • 一大（子类 $\ge$ 父类）：
    1. 访问权限大（或相同）：如果父类是 protected，子类可以是 protected 或 public，但绝不能是 private 或 default。

3. 代码示例

class Father {
    // 父类方法
    protected Object doSomething(String msg) throws IOException {
        System.out.println("Father is doing: " + msg);
        return new Object();
    }
}

class Son extends Father {
    // ✅ 正确重写：
    // 1. 两同：方法名 doSomething，参数 String msg
    // 2. 一大：访问权限 public > protected
    // 3. 两小(返回值)：String 是 Object 的子类 (协变返回)
    // 4. 两小(异常)：不抛出异常 (比 IOException 小)
    @Override 
    public String doSomething(String msg) {
        System.out.println("Son is doing: " + msg);
        return "Success";
    }
}

(注：强烈建议在重写方法上加上 @Override 注解，让编译器帮你检查是否真的构成了重写，避免拼写错误导致意外重载。)

4. 不能重写的情况（避坑指南）

  • private 方法：对子类不可见，子类定义同名方法只是子类自己的新方法，不是重写。
  • final 方法：被 final 修饰的方法禁止被重写。
  • static 方法：静态方法属于类，不属于对象。子类定义同名静态方法叫隐藏（Hide），不叫重写。
  • 构造方法：构造方法名必须与类名相同，父子类名不同，所以构造方法不能被重写（但可以被重载）。

5. 重写的绑定机制

重写是在运行阶段才决定执行哪个方法的。当通过父类引用指向子类对象（多态）并调用方法时，JVM 会在运行时根据对象的实际类型（而不是引用变量的声明类型）去方法区查找并执行对应的方法。因此，重写被称为运行时多态或动态绑定。

四、 总结与经典面试题

💡 总结对比图

【重载 Overload】                 【重写 Override】
  同一个类中                        父子类之间
  方法名同，参数不同                方法名、参数完全相同
  编译时多态 (看参数)               运行时多态 (看对象实际类型)
  关注的是“提供多种功能”            关注的是“改变原有行为”

❓ 经典面试题自测：

  1. 构造方法能被重载吗？能被重写吗？
    • 答：可以重载（同一个类中可以有多个参数不同的构造方法），但不能重写（因为构造方法名必须和类名一致，父子类名不同）。
  2. 重载和重写，哪个是多态的体现？
    • 答：严格意义上，重写是Java运行时多态的核心体现。重载通常被称为编译时多态（或静态多态），但在某些语境下，面试官只认重写为真正的多态。
  3. 如果子类重写了父类方法，如何在子类中调用父类被重写的方法？
    • 答：使用 super.方法名(参数)。
